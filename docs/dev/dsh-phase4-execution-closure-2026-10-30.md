# 阶段四：执行闭环与前端可见性（2026-10-30）

## 已完成

### 执行状态

| 状态 | 表示 | 说明 |
| --- | --- | --- |
| `proposed` | 待处理 | 决策已出，尚未执行 |
| `approved` | 已批准 | 原生审批放行 |
| `executing` | 执行中 | 已派发 |
| `executed` | 已执行 | 有完成回调且未标未知 |
| `failed` | 失败 | 宿主报告失败 |
| `cancelled` | 已取消 | 未派发即取消：工具没有执行，不计失败 |
| `outcome_unknown` | **结果未知** | 派发已发生但确认丢失；既不记成功也不记失败 |
| `blocked` / `rejected` | 阻断 / 拒绝 | 策略拒绝与用户拒绝分开 |

- 概览计数新增 `blocked`、`unknown`、`cancelled`：`unknown` 单独计数，`executed` 排除未知。
- 派发确认丢失的补交记录为 `outcome_unknown`，不再被 `after_tool_call` 改写成 `failed`。
- 插件在结果回调时上报 `cancelled`（`exec.signal.aborted`）；服务端仅在未派发时采纳，派发后取消仍按未知处理。

### 前端

- 动作卡片新增「决策依据」：决定层、支配原因码、其它原因码、命中规则、缺失证据、带角色的资源、审批发起方与执行面、任务授权 ID、命令类别。
- 「结果未知」作为独立状态展示，并在动作列表提供独立筛选项（`unknown_result`）。
- 内层调用（`parent_call_id`）显示「内层调用」标签与父调用 ID。
- 动作列表按父调用折叠内层调用：有父调用的条目收进父条目的「内层调用」折叠区，找不到父条目的内层调用仍单独展示。
- 「结果未知」「已取消」均有独立筛选与状态文案。
- 设置页新增「任务授权」只读面板：范围、剩余时间、已批准命令类别。
- 设置页新增「审批归因」面板：按支配原因统计已记录的审批与阻断。
- 概览新增去重指标：任务授权放行数与命令复用数（`actions.dedup`），以及 `actions.approvals` 归因聚合。
- 后端不可用状态沿用宿主 UI 的离线横幅与重连（`EmbeddedShell`、`useGuardSync`），动作层不再混入该状态。

## 阶段三收尾说明

- 规则范围修正：阶段二已完成主要项（文档读取、敏感标记、密钥/管理员事实、资源污染、持久化组合、别名规则）。复查剩余阻断规则后确认：`NATIVE-CMD-002/003`、`NATIVE-SKL-005`、`NATIVE-CFG-002/005` 均已用 `operation` 限定，关键字事实不会跨操作误阻断。
