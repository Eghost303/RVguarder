# 宿主 Agent 语义委派设计

日期：2026-10-28  
状态：已获用户批准，待文档复核  
优先级：DSH 首发；接口为后续 OpenClaw 适配预留

## 目标

让 RVguarder 在工具调用审批热路径中，将受限的语义分析交给所连接宿主的隔离子代理执行，复用宿主配置的模型路由和凭据。RVguarder 不为这条路径单独连接模型 API，也不把子代理的回答当作授权裁决。

首发必须先在当前支持的 DSH 0.2.1-rc.2/rc.3 集成中可用。DSH 未达到安全调用条件时，此模式报告不可用并退回本地规则分析；不能假称子代理模式已启用。完成 DSH 后，再用 OpenClaw 专用适配器实现同一语义委派合约。

## 当前边界

- DSH 插件 `dshRVguarder/src/index.ts` 在 `tools/pre-execute` 中把调用送往 Python 后端；Python `DshServices` 持有 `DshSemanticEnhancer` 并在后端决策流水线中分析语义。
- 当前 `SemanticEnhancer` 直接请求 DeepSeek Chat Completions，默认凭据来自 `DEEPSEEK_API_KEY` 或 `guard-config.json`。
- DSH 设置接口当前支持 `local`、`auto`、`llm`。本设计新增宿主子代理模式，同时保留现有模式以兼容既有配置。
- OpenClaw 当前集成具有普通 `chat.send`，但它会向用户会话发送内容，不能用作审批热路径里的子代理。OpenClaw 后续适配必须调用其隔离子代理能力，并遵守插件 SDK 的上下文资格和权限限制。

## 方案

采用共享 Python 语义协议、各宿主原生子代理调用器：

1. DSH 插件在 `tools/pre-execute` 中先向 Guard 后端请求本次调用的语义分析材料。
2. 后端基于现有 `build_sanitized_llm_input` 产生经过裁剪、脱敏的请求。该准备阶段不作授权裁决，不写执行许可，也不改变现有审计状态。
3. DSH 插件通过宿主正式支持的子代理接口请求一次隔离、无工具的语义分析。只允许传递准备阶段返回的净化材料，不把原始工具载荷或完整会话交给子代理。
4. 插件将子代理的原始结构化回答附加到原调用的 Guard 请求。Python 核心验证大小、协议版本和受控 schema，再合并确定性本地语义，继续原有 Authorization Trace、PMKB 和 RV 流程。
5. 子代理结果只作为 `suggested` 语义证据。PMKB/RV 仍是唯一授权决策者，模型不能直接 allow、ask、block，也不能降低 PMKB 裁决。

DSH 和 OpenClaw 使用同一请求/响应 schema，但各自实现宿主调用器。调用器只负责受限的子代理生命周期和原始响应交接，不拥有授权逻辑。Python 侧保留独立的 `HostSemanticProvider`/传输边界，禁止在共享决策核心内读取宿主密钥或直接访问宿主 SDK。

## DSH 首发门槛

实施开始时先核对 DSH 0.2.1-rc.2 和 rc.3 实际可用的插件 API；仓库中的开发说明或上游主分支接口本身不能代替对这两个目标版本的验证。要启用 DSH 宿主子代理模式，必须同时满足：

- 宿主以当前已配置的模型路由和凭据运行子代理，不要求用户再配置 RVguarder 专用 API 密钥。
- 能请求一次性、隔离的子代理调用，并取得最终文本结果。
- 子代理没有工具执行能力，或宿主提供等效、可验证的最小工具策略；不能以“只在提示词里要求勿调用工具”代替权限限制。
- 调用可由原 `tools/pre-execute` 生命周期等待并有硬超时；取消/超时不会继续等待子任务，也不会改变现有策略 fail-open/fail-closed 语义。
- 如果当前 SDK 没有满足上述条件的接口，先完成必要的 DSH 插件侧适配或将该模式明确报告为不支持；不得退回到普通用户会话、无约束子代理或私有 API 请求。

## 模式与兼容

- 新增显式 `host-agent`（或等价命名）语义模式，避免用户未选择时意外向宿主模型发送工具信息。
- `local` 继续强制使用本地规则。
- 既有 `auto` 和 `llm` 保持现有含义，避免静默改变旧部署行为；本任务不把直接 API 模式伪装成宿主子代理。
- 子代理不可用、超时、拒绝或输出不符合 schema 时，`host-agent` 降级到本地语义分析，并在状态/审计中记录固定原因码；不记录密钥、完整提示词或原始子代理对话。
- 前端和状态 API 清楚区分 `local`、直接 API、宿主子代理，以及最后一次委派状态；不暴露子代理凭据。

## 安全与运行限制

- 子代理仅获得净化后的单次语义任务，不继承用户聊天历史、文件附件或 RVguarder 工具。
- 回答按不可信输入处理：严格解析 JSON、拒绝额外字段/越界文本，并使用现有受控 operation/fact allowlist 与工具名校验。
- 子代理只能增加建议证据。确定性本地投影始终执行；语义调用失败只影响语义增强，不绕过 PMKB/RV，不改变宿主既有工具审批结果。
- 通过请求 ID 绑定原始工具调用、实例和会话，拒绝跨请求重放或错配响应。准备阶段和完成阶段均使用现有本地认证令牌及请求大小限制。
- 配置单次调用超时、输出字节上限及并发/频率预算。预算耗尽时直接使用本地分析。
- DSH 插件返回或异常路径必须释放子代理资源，并保证宿主工具调用继续遵从当前配置的审批及后端故障策略。

## 验收标准

1. DSH 0.2.1-rc.2 与 rc.3 各自完成实际运行时核验；当前部署所用版本有可复核证据。
2. 启用 `host-agent` 后，不配置 RVguarder 独立 LLM API 密钥，仍能由宿主隔离子代理产生语义建议。
3. 子代理只收到净化输入且没有工具权限；测试记录证明 PMKB/RV 仍作出最终裁决。
4. 超时、取消、不可用、畸形输出、过量输出、错配 request ID、预算耗尽均回退本地语义分析，不导致额外阻断或直接放行。
5. `local`、`auto`、`llm` 既有行为兼容；状态 API 可区分委派成功与回退原因，不泄漏秘密或自由文本提示内容。
6. DSH 首发通过后，共享请求/响应合约能够由 OpenClaw 适配器复用；OpenClaw 适配不得使用普通 `chat.send`。

## 明确不做

- 不实现独立 API 多供应商配置或凭据发现。
- 不让子代理作权限裁决、签发许可或影响审计哈希链。
- 不复用用户的普通聊天会话，不复制完整历史给子代理。
- 不在本阶段实现 OpenClaw 适配器；仅保持共享合约可扩展，DSH 可用性优先。

## 主要风险

- DSH 0.2.1-rc.2/rc.3 的真实 SDK 接口可能不具备所需的一次性、无工具推理能力，需以固定版本运行时核验为准。
- 子代理推理延迟可能超过同步审批热路径预算；必须设置超时并保留本地确定性回退。
- DSH 默认子代理能力可能继承过宽的工具集；若无法建立无工具策略，就不能启用该模式。
