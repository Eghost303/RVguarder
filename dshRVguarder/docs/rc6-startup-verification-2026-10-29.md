# rc.6 启动目录修复与复验

> 历史验收记录，保留原版本与原结论；当前 **v0.2.1-rc1** 的使用入口和范围见 [安装指南](deployment.md) 与 [版本说明](release-current.md)。

rc.5 遗漏了从用户主目录直接执行 `dsh rvguarder-dev` 的场景。其后台数据位于用户目录下，而旧实现又将启动 cwd 当作后台资源根，因此在后台启动前被包含关系检查拒绝。独立脚本切换目录使该缺陷未在此前验收中暴露；此前“任意启动目录开箱即用”的结论撤回。

## 修正

- 自动托管后台按 DSH_HOME 与 profile 绑定身份、数据及资源根；默认资源根为 `<DSH_HOME>/workspaces/<profile>`。不读取启动 cwd 作为后台实例绑定，不修改宿主或会话工作目录。
- 普通工具的 cwd 继续来自已认证 SDK 调用上下文。事件中的真实工作目录与后台受控资源根分别记录，工具参数不能冒充 cwd。
- 私有数据、状态和运行时不能落入已登记受控资源根；保留实际路径检查、私有 ACL、实例独占、认证和恢复锁定。可选宿主配置 `resourceWorkspace` 明确登记受控资源根，签名字节执行器仍只能在该根内工作；不会因启动目录更宽而扩大签名资源范围。
- 管理入口同步初始化错误保留固定分类，资源目录冲突显示 `workspace-conflict`，配置无效显示 `configuration-invalid`，不再统一误报后端不可达，也不向浏览器回传路径。
- 开发脚本仅选择 `rvguarder-dev`，不再切换目录。用户可直接使用 `dsh rvguarder-dev`。

私有 ACL 不等于隔离同一用户的任意完整权限进程；这不是系统级沙箱的验收声明。PMKB、授权规则和审批语义未改。rc.2 UI、其他平台与此前未关闭的规则链问题不因本轮启动修复计为通过。

实现回归：Python DSH 52/52；Node 路径、管理及冻结程序定向 27/27；组件 15/15。包含启动 cwd 为用户目录、DSH_HOME、数据父目录、普通项目及盘符根的固定绑定检查，以及不修改宿主默认目录、真实工具 cwd 与后台资源根分离、错误分类及中英文提示。
